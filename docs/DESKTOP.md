# Windows 桌面预览版

当前分支：`codex/windows-desktop`。React 界面由 Windows WebView2 显示，FastAPI 后端随进程运行。无需用户安装 Python、Node 或启动浏览器。

## 打开

双击 `release/CryptoSignalCopier/CryptoSignalCopier.exe`。分发时必须复制整个 `CryptoSignalCopier` 文件夹，包括 `_internal`，不能只复制 EXE。需要 Windows 10/11 和 Microsoft Edge WebView2 Runtime。

数据位于 `%LOCALAPPDATA%/CryptoSignalCopier`。EXE 更新不会覆盖用户数据。密钥和 Telegram 会话使用 Windows DPAPI 加密，绑定当前 Windows 用户；复制到其他电脑不能直接解密。日志为 `desktop.log`，信号、收信记录和审计为 SQLite。普通 Web 开发模式仍使用 backend/.env，请勿将此文件打包或分发。

窗口打开期间执行监听和跟单，关闭窗口会停止后端。应用只允许同一数据目录运行一个实例。本地 API 使用随机端口、每次启动的会话凭证和 Origin/Host 校验，不对局域网开放。

## 配置与实际验收

1. 打开“连接管理”，选择 Bitget 模拟盘，填写模拟盘 API Key、Secret、Passphrase，勾选“允许向 Bitget 模拟盘提交订单”，验证保存。本版下单对接经典 USDT 合约 V2；UTA 账户支持只读，不支持 UTA 模拟盘下单，界面会阻止错误配置。普通实盘 Key 不能用于模拟盘。
2. 在同一页填写自己的 Telegram API ID、API Hash 和带国家区号的手机号，保存。点击发送验证码，填写 Telegram 中收到的验证码；有两步验证则继续填写密码。验证码和密码不持久化。
3. 刷新频道列表，勾选账号已加入的频道/群组并保存。打开侧边栏“Telegram 消息”，左侧显示实际保存的监听频道名称和 ID；选中频道自动补读最近 30 条，后续新消息通过 WebSocket 推送到桌面。普通消息、附件消息和解析失败原因也会显示。仅接收已选来源，Telegram 连接状态与桌面推送连接状态分别显示。
4. 在“信号追踪”设置固定保证金或权益比例、杠杆和市价/限价方式，开启自动执行并保存。程序对新完整信号下单，附带止损和第一个止盈。已收到的旧信号不会因为打开开关而重放。
5. 等待所选频道发出新消息，确认“接收记录 → 解析信号 → 审计事件 → 模拟盘订单 ID → Bitget 模拟盘实际订单”一致。这个步骤必须由真实登录账户完成，不能用 mock 测试代替。
6. 重启应用，检查登录恢复和频道选择；关闭自动执行后再接收一条消息，确认仍收信但不下单。

支持的完整信号格式示例（价格仅为格式示例，不建议直接下单）：

```text
ETHUSDT SHORT
Entry: 3700 - 3720
SL: 3785
TP1: 3560
TP2: 3440
```

支持中文“做多/做空、入场、止损、止盈”。本版不会猜测缺失价格、识别图片或跨多条无明确关联的消息拼接订单。不完整信号仅记录原因。市价与参考入场相差超过 2%、消息延迟超过 120 秒、低于最小下单量时拒绝跟单。数量按交易所步长向下取整；杠杆受合约上限限制。

支持分开发出的开单和保护参数：例如 `#UAI 市價多 0.45091`，随后直接回复该消息 `止盈：0.479-0.511-0.551` 与 `止损：0.425`。按同频道 Telegram reply ID 关联，不按币种或邻近时间猜测。开单显示“等待止盈止损”；止盈止损齐全且价格关系有效后才生成一个以开单消息 ID 为身份的信号，两条原文一起显示。重复回复或重启重投不会重复下单。所有止盈展示供核对，现有模拟盘执行仍只附带第一个止盈，并非分批止盈。

自动执行要求开单为实时收到的未编辑消息、回复在开单后 15 分钟内且自身未超过 120 秒；仍需通过原有价格偏离和账户风控。历史开单补读、编辑消息、缺失回复目标、币种冲突、包含歧义的新方向/入场信息均不自动跟单。无 Telegram 回复关系的转述、截图、纯引用文本，以及分三条分别发送止盈和止损暂不自动拼接。等待参数会错过第一条的即时成交价，这是避免无保护开仓的默认取舍。

“Telegram 消息”可逐项对照原文与解析参数，查看关联执行结果与审计，并跳转对应信号。解析成功不代表策略正确或保证盈利。历史补读只用于查看，不触发下单；编辑消息会更新原文与解析预览，不修改已生成订单或重复下单。照片支持按需预览，其他附件显示类型与文字说明，不支持播放或图片信号 OCR。最多保存最近 10,000 条接收记录，页面显示所选范围最新 100 条；补读最近 30 条不是完整离线消息归档。

“已提交模拟盘”仅表示交易所接受订单，不代表已成交。下单超时通过 clientOid 查询一次；结果仍不明时标记待核对，不自动重复下单。进程在提交期间中断的记录也须人工对照交易所核对。

“市场行情”每 15 秒读取真实公开行情和 15 分钟 K 线；断网显示错误与上次更新时间。经典账户资产、持仓和挂单通过 REST 刷新，UTA 只读账户另支持私有 WebSocket。当前不是逐 tick 行情回放系统。

## 程序内持续跟单模拟

“实盘模拟”使用公开 Bitget 标记价，不需要交易所个人 API。Telegram 频道跟单仍需 Telegram 登录并选择监听频道。

- 创建时可填写独立模拟 ID、本金、杠杆并勾选博主；留空 ID 自动生成。同时运行一个模拟 ID，已结算 ID 不可覆盖。旧版账本迁移为 `legacy-simulation`，持仓不清空。
- 后端每 5 秒监控持仓，不必停留在该页面。关闭程序停止收信和行情观察，但不结算；重新打开后恢复未停止的 ID、持仓、频道策略和去重记录。离线期间不补造交易，重开按新行情继续处理持仓。
- “停止跟单并结算”须在应用内确认。它按新获取的公开行情平掉模拟持仓、计入平仓手续费，取消未成交订单，冻结并归档报告。取价失败时不会用旧价强行结算，可恢复网络后重试。新建模拟保留旧结算，可从报告下拉框查看。
- 曲线按 UTC 日保存最后一次有效估值，支持放大/缩小、起止日期滑块和悬停查看余额、权益、当日与累计净收益。余额不含浮盈，权益含浮盈；当日尚未结束，停止日以结算时刻为终点。离线无采样日留空，跨缺失日不计算伪造的当日收益。在线不足全天的点不是精确午夜估值。
- 显示创建至结算的时间跨度和累计在线运行时长。在线时长按心跳持久化，异常退出最多丢失最近心跳间隔；长时间挂起不计为持续运行。
- 市价多/空信号按公开价格模拟成交（偏离参考入场超过 2% 或已越过止盈止损则拒绝）；区间信号仍等待价格进入区间。仓位按账户权益、信号风险比例与止损距离计算，多档止盈等份减仓，默认模拟手续费每边 0.06%。

这是用于收益测试的本地模拟，不等同真实交易所撮合：没有逐 tick 回放、资金费率、订单簿滑点与真实强平模型，关闭/断网期间不能模拟触发顺序，不能承诺与实盘结果一致。

## 构建与测试命令

```powershell
backend/.venv/Scripts/python.exe -m pip install -r backend/requirements-desktop.txt
# 首次在 prototype 安装 package.json 中的依赖
./scripts/build-desktop.ps1 -Node "node" -Python "完整路径/backend/.venv/Scripts/python.exe"
cd backend
.venv/Scripts/python.exe -m pytest -q
```

EXE 自检：

```powershell
release/CryptoSignalCopier/CryptoSignalCopier.exe --smoke-test --data-dir "一个独立测试目录"
release/CryptoSignalCopier/CryptoSignalCopier.exe --ui-smoke-test --data-dir "另一个独立测试目录"
```

结果写入测试目录的 JSON；HTTP 自检需要访问公开 Bitget 行情，UI 自检会打开并关闭窗口。不会连接私人 Telegram 或提交订单。

## 收费发布前仍需完成

当前是可运行、可打包的桌面预览版，不包含付费授权服务、支付、订阅到期处理、签名安装器、自动更新或代码签名。商业化适合单独实现服务端签名许可证与订阅校验；不要只在客户端放一个可修改的“已付款”开关。正式分发前还需完成真实模拟账户长时间断线重连和回执验收。

实现参考：[pywebview 打包](https://pywebview.flowrl.com/guide/freezing)、[Telethon 授权](https://docs.telethon.dev/en/stable/modules/client.html)、[Bitget 合约交易](https://www.bitget.com/docs/catalog/classic-contract-trade/classic-contract-trade)。
