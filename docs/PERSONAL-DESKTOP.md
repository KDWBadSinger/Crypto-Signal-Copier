# 个人桌面版 0.3 使用与验收

## 打开

运行 `release/local-0.3/CryptoSignalCopier/CryptoSignalCopier.exe`。整个目录一起保留，不单独移动 EXE。
不需要部署服务器；本地授权服务默认不是交易前提。需要 Windows、WebView2 和可访问 Telegram、Bitget 的网络。
本版没有代码签名，也未完成真实资金账户验收；不能以隔离测试代替交易所实测。

## 启用顺序

1. 连接管理：在本机填写 Telegram API、完成验证码/二步验证，选择监听频道。不要将密钥发到聊天。
2. 连接管理：连接 Bitget **实盘 UTA**，检查 UTA 交易与管理权限；不授予提现权限。
3. 信号追踪：设置实盘保证金比例、最高杠杆、仓位数量并保存。默认 6%、10 倍、5 个；硬限制 7%、30 倍、6 个。币种杠杆覆盖仍受此上限约束。
4. 展开“启用真实资金自动交易”，阅读风险、输入确认文字后，由用户本人点击启用。保存 API 或参数本身不启用下单。
5. 在 Telegram 消息中核对原文、回复关系与解析结果；在信号追踪查看交易所保护状态。

## 交易与恢复行为

- 目前实时自动执行的是已支持格式的 USDT 永续市价跟单，止盈档位等量分配，末档处理数量舍入余量。
- 必须收到完整开单与保护信息；拆分消息只按同频道直接回复 ID 合并。历史、编辑、过期消息不追补。
- 每次下单重新读取净值，按保证金比例和受限杠杆计算数量。交易所最小数量/金额及止盈分档不满足时拒单，不擅自扩大金额。
- 同币种存在手动仓位、挂单或未知策略时不接管。不要在正在跟单的币种上手动交易，否则会暂停核对。
- 开单预设止损；成交后将空币种开仓时间窗口内唯一匹配的预设止损绑定到本地记录，不再复制一个止损。无法唯一核对时停止新开仓。
- 止盈触发后读取策略历史、子单与成交明细，对齐剩余仓位并调整止损；全部平仓后取消本程序残留保护单。
- 成本损包含实际开仓手续费和按公开 taker 费率预估的平仓费，不包括资金费。格局保留当前剩余数量的 10%，目标为其开仓保证金 500% 毛收益。
- 明确取消或失败的止损，在持仓与本程序成交数量完全对齐后，会触发只减仓市价退出。结果不确定时先查询，不盲目重发。
- “停止新开仓”仍保留现有持仓管理。关闭 EXE 后不接收新消息；交易所已接受的保护继续执行。重启后先核对，再恢复此前启用的跟单意图。
- 超时、网络中断、策略历史尚未同步会显示“等待核对”，后台每 5 秒尝试恢复；也可点击“立即核对 / 恢复”。不允许通过清除数据库强行重试未确认订单。
- 如 API 返回无法验证的状态或账户有外部交易，程序可能需要人工在交易所核对。这是异常暂停，不是保证任何错误都能无人工恢复。

## 收益口径与本地数据

实盘曲线只累计归属于本程序的已核对成交盈亏减交易手续费，不包括资金费与未实现盈亏，不将充值提现当收益。账户权益观察是另外的曲线。

数据保存在 `%LOCALAPPDATA%/CryptoSignalCopier`，升级前有 SQLite 备份；密钥由本机 Windows 账户保护。不要删除数据目录来解决订单异常。旧版本仍在运行时先正常退出，再打开新版；不要强制结束有未确认请求的进程。

## 验收边界

自动测试使用假的交易所响应、隔离数据库和虚构资金，覆盖 Telegram 拆分信号接入、资金限制、部分成交、保护、减仓、断线恢复、结算、去重。
发行目录中的 EXE 还需真实账户小额验收，以确认该账户实际返回的预设止损、策略子单、手续费等字段与接口文档一致。未经用户在本机明确启用，不进行真实交易。

接口参考：[Bitget V3 策略交易](https://www.bitget.com/docs/catalog/trading/strategy-trading)、[订单管理](https://www.bitget.com/docs/catalog/trading/order-management)。
